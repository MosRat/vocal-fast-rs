# Complete voice bundles and automatic TensorRT plans

The model library displays **Synth**, **HuBERT**, **RMVPE**, and **Index** for
each entry. Component details report their source, tensor count, and weight
size. Index is optional; its absence does not prevent plan preparation.
Acoustic packages can be inspected but cannot be loaded as voice models.

Both RVC v1 and v2 are supported by CPU, DirectML and TensorRT. V1 bundles
must include the trained HuBERT `final_proj` parameters; a v2-only acoustic
package cannot supply them. Version selection, conversion and measured parity
are documented in [RVC v1 support](rvc-v1-support.md).

## Load workflow

1. Select a complete voice bundle or a Synth-only voice in Studio.
2. Select Automatic or a supported backend.
3. Click **Load**. Complete bundles extract their embedded acoustic packages.
   For Synth-only voices, Studio checks the shared cache and offers one
   consented download from `MosRat/vfrm-models`; the verified files are bound
   into a derived complete VFRM and then loaded automatically. Local HuBERT and
   RMVPE files can be selected from the same setup card.

Studio and Settings initially show the embedded component locations. After
loading, they show the actual cached `hubert.vfrm`, `rmvpe.vfrm`, and generated
`pipeline.json`. These derived paths are persisted with the model and backend
in one revision-checked Runtime command. Unrelated unsaved settings remain
drafts. Load uses the **saved** session profile; save profile edits first.

Startup restoration uses the same automatic preparation path. Audio sessions
lock configuration and loading; preparation also locks the controls across
windows. A failed build or load preserves the previous model, engine, and
persisted configuration. The existing error action restores the idle state.
The original Synth-only package is never modified. Its derived complete VFRM
is stored in the per-user cache, so all three backends consume the same
resolved model without manually entering backend source paths.

## Container and memory policy

A complete bundle retains the `rvc-synth-v1` Synth directory and optional
`aux.retrieval.faiss` byte tensor. Two additional one-dimensional U8 tensors
contain standalone `acoustic-v1` VFRM files:

| Tensor | Required component |
| --- | --- |
| `aux.hubert.vfrm` | HuBERT |
| `aux.rmvpe.vfrm` | RMVPE |

Inspection validates the outer directory and both embedded directories,
including schema/kind, canonical shapes, mapping, duplicate names, overlapping
ranges, checked offsets, and file bounds. It reads metadata/directories only;
directory allocation is capped at 32 MiB and library metadata at 4 MiB per
container. There is no recursive bundle nesting.

`load_voice_cache_shared` loads only Synth and index payloads. Runtime and GUI
Synth preparation use it, so unused acoustic payloads are not retained in the
voice package. The full `load_cache[_shared]` APIs still preserve every tensor;
full and voice-only packages have distinct weak cache entries.

Bundling and extraction stream bytes with bounded working memory. Temporary
files are validated and flushed before publication; incomplete writes are
removed. Valid extracted sources and plans are reused. Source identities use
canonical path, size, and modification time. Plan cache identities also include
the complete native build policy, shape profile, GPU/driver identity, cache
version, and deployed TensorRT library identity. These are local performance
caches, not content-addressed archives; do not mutate their cached files.

## Creating a complete bundle

Use canonical sources generated by the existing converters:

```powershell
rtk cargo run -p vocal-model --example bundle-rvc -- `
  target/default-canonical-with-index.vfr `
  models/shared/hubert_base/hubert_features.vfr `
  models/shared/rmvpe/rmvpe.vfr `
  target/default-complete-with-index.vfrm
```

Existing output files are refused. Model weights, extracted sources, and plans
remain local generated assets and must not be committed.

## Validation

Windows RTX 3060, SM 8.6, CUDA driver API 13.4, TensorRT RTX 1.6.1:

- Real Default Voice bundle: 353 Synth, 227 HuBERT, 310 RMVPE tensors, plus its
  retrieval index; approximately 818 MiB on disk.
- First automatic build and engine load: **24.1 s**, cache miss.
- Second Load: **7.3 s**, plan cache hit, including engine/context loading.
- Native WebView tests checked catalog variants, all four component badges,
  automatic source paths, one-revision commit, unrelated draft preservation,
  acoustic-only rejection, Settings paths, and failed replacement recovery.
- Parser tests cover extraction reuse/repair, selective cache separation,
  swapped acoustic kinds, oversized directories, and truncated payloads.
- Restart restored the complete bundle through the automatic cache path.
  A load initiated through another controller locked both backend and session
  profile controls through channel status updates.
- A separate offline Runtime processed 480 mono 48 kHz blocks of 480 samples
  through the generated GPU pipeline. Outputs were finite and became nonzero
  after the existing startup warmup. This checks streaming execution, not voice
  quality or physical device latency (`complete-model-inference.json`).

Affected package tests and formatting passed, along with the all-features
workspace check and workspace tests (125 passed, 4 ignored). The global fmt
check still reports formatting differences in the separately edited DirectML
files; these were not reformatted by this change.

Reports and screenshots are local under `target/windows-build/Debug-TensorRt/`,
including `model-bundle-regression.json` and `model-complete-settings.png`.
These measurements cover preparation and loading, not physical audio latency.
